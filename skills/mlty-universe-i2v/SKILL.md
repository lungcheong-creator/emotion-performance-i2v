# MLTY Universe I2V Production

将 `@skill:nano-banana-2` 生成、且**经用户确认**的分镜头静帧，转换成 3–15 秒（建议 5/8/10/15 秒）的动态视频，可带**原生音轨与口型同步对白**。

支持的模型（`--model` 三选一，**没有默认，调用方必须显式指定**）：

| `--model` | 真实 model id | 用途 |
|---|---|---|
| `kling` | `kling-3.0/video` | 单张首帧 → 动态；唯一支持 `negative_prompt`、4K mode、**音色参考（`--voice-ref`）** |
| `omni-image` | `kling-3.0-omni/image-to-video` | 单张首帧 → 动态；原生 1080p/4K、可多镜头、`audio: true` 可出音轨（**音色参考未验证**） |
| `omni-reference` | `kling-3.0-omni/reference-to-video` | 多张参考图（**上限 7 张**）锁人物/服装/场景 → 动态 |

参数细节、字段名差异与三个模型的实测边界，权威表在
`@skill:emotion-performance-i2v` 的 `references/models.md`，不要在本文件重复维护。

**`aspect_ratio` 三个模型三种规矩，别统一：**

| `--model` | `aspect_ratio` |
|---|---|
| `kling` | 可选；有图时自动适配 |
| `omni-image` | **只能 `auto`**（送 `16:9` → 422）。输出比例**继承输入图**，要 16:9 必须先把输入图正規化成 16:9 |
| `omni-reference` | **必须给具体比例**（`16:9`）；送 `auto` → 500 |

`resolution` 对 omni 必须显式传（API 默认 720p，会静默降级）。

## 触发条件（硬性闸门）

- 仅在用户**确认**了 nano-banana-2 的分镜画面后调用本 skill。
- 未确认、或只是草稿，不要直接跑。先把图给用户看，等“确认/可以了”再转。
- 凭证已在 `config.json`（chmod 600），不在源码里。

## 時長規則（3–15 秒，**不再強制壓到 8 秒**）

API 對三個模型的 `duration` 範圍都是 **3–15**（2026-09-25 實測）。工作流建議的檔位是
**5 / 8 / 10 / 15 秒**，但任何 3–15 的整數都合法。

**超出範圍是硬錯誤（`DURATION_OUT_OF_RANGE`），不是靜默壓縮。**
（舊版 `MAX_DURATION = 8` 會把請求的 10s 默默變成 8s——已移除。靜默降級比失敗更糟。）
確定要接受被縮短的版本才加 `--allow-duration-clamp`。

## 原生音訊與對白（2026-09-26 新增）

**Kling 3.0 在同一次生成裡就渲染出環境音、音效、配樂與口型同步的語音**，
所以對白**不需要後期**。這不是「音效開關」，是完整的原生音軌。

| 項目 | 做法 |
|---|---|
| 開關 | `--audio`（kling 送 `sound: true`；omni 送 `audio: true`） |
| **對白** | `--dialogue "台詞"`（或 manifest 的 `dialogue` 欄位）。**腳本會把它組進提示詞的引號內**——那是 Kling 唯一會讀對白的地方 |
| 語氣 | `--dialogue-style "whispers"` / `"says calmly"`（預設 `says quietly`） |
| 音色 | `--voice-ref <5–30s 音訊>` 對應 `kling_elements[].element_input_audio_urls`（**kling 專屬**） |
| 元素引用 | `--element-images a.jpg b.jpg` ＋ `--element-name`，提示詞用 `@名稱` 引用（每個 `@名稱` 佔 37 字元，最多 3 個元素） |
| 成本 | 約 **+43–50%**（pro 無音 18 → 有音 27 credits/秒；std 14 → 20） |

**兩個必知的坑：**

1. **對白只寫在 manifest 不會被唸出來** → 產出**完全沒聲音**的片子（畫面一切正常）。
   用 `--dialogue` 就自動組進提示詞。
2. **對白過長會硬擋（`DIALOGUE_TOO_LONG`）**。判斷依據是語速模型
   （中文 3.5 字/秒、英文 2.5 詞/秒，含標點），並依時長給出可說話的秒數
   （5s→2.5s／8s→3.5s／10s→4.5s／15s→6s）。
   過長必定口型失準（首字與尾字最容易飄）。`--allow-long-dialogue` 可覆寫。

**生成後務必驗收音軌**（`@skill:emotion-performance-i2v` 的 `scripts/check_audio.py`）：
確認有音訊流、有語音事件、落點符合設計。沒有聲音的片子從檔名到解析度都看不出來。


## 调用方式

脚本：`scripts/i2v.py`（纯标准库，无需装包）。

### 方式 A：单条 / 快速测试
```bash
python3 scripts/i2v.py \
  --image /path/to/confirmed_frame.png \
  --prompt "slow push-in, gentle camera drift, soft film grain" \
  --duration 5 \
  --output-dir /tmp/mlty_out
```

### 方式 B：分镜清单（推荐，批量）
把每个确认的分镜写成 JSON manifest，顺序即镜头顺序：
```json
[
  {"image": "/frames/shot1.png", "prompt": "wide establishing, slow aerial rise", "duration": 8},
  {"image": "/frames/shot2.png", "prompt": "product close-up, subtle rotate", "duration": 5},
  {"image": "https://.../shot3.png", "prompt": "motion blur transition", "duration": 8}
]
```
```bash
python3 scripts/i2v.py --manifest /tmp/shots.json --output-dir /tmp/mlty_out
```
- `image` 可为**本地路径**（自动上传到 Kie.ai 取 downloadUrl）或 **http(s) URL**（直接用）。
- **⚠️ 本地路径必須絕對路徑（2026-09-26 實測）**：`i2v.py` 以**進程 cwd** 解析相對路徑，不吃 manifest 所在目錄；由 agent 背景執行時背景 shell 不繼承前一條命令的 `cd`，相對路徑直接 `FILE_NOT_FOUND`（發生在建單前，零成本，但要重發）。`--manifest` / `--output-dir` 同理全部用絕對路徑。
- **⚠️ manifest 頂層必須是 JSON 陣列**：包成 `{"shots": [...]}` 會在 `_shot_images` 報 `'str' object has no attribute 'get'`。
- `prompt` 是运动提示词（描述怎么动，不是画面内容）。
- `aspect_ratio`：有图时 Kling 自动适配，省略即可；需强制指定时给 16:9 / 9:16 / 1:1（Kling 无原生 21:9 → 生成 16:9 再用 ffmpeg crop）。
- `negative_prompt`：manifest 加 `negative_prompt` 字段，或用 `--negative-prompt`。Kling 3.0 支持，默认不发送。
- 可选：`mode`(std/pro/4K，默认 pro)、`audio`/`dialogue`/`dialogue_style`(见「原生音讯与对白」节)。 **`sound`/`audio` 不是只有音效——开下去就是完整的原生音轨。**

### 关键参数
`--image` / `--manifest`（必填其一）、`--model`（**必填，kling / omni-image / omni-reference**）、
`--duration`、`--mode`（仅 kling）、`--negative-prompt`（仅 kling）、`--audio`、`--resolution`（omni 建议显式 1080p）、
`--output-dir`、`--poll-interval`(默认5s)、`--max-poll`(默认120)、`--dry-run`、`--allow-non-169`、`--allow-duration-clamp`。

**原生音频与引用相关（2026-09-26 新增）：**
`--dialogue`、`--dialogue-style`、`--allow-long-dialogue`、
`--voice-ref`（5–30s 音频，锁音色，kling 专属）、`--element-name`、`--element-images`（2–4 张，可重复）。

**manifest 也支持对应字段**：`dialogue`、`dialogue_style`、`speaker`、
`voice_ref`、`element_name`、`element_images`、`element_description`。

### 先干跑再发射（强烈建议）
`--dry-run` 会照常上传图片、组好 createTask 请求体，但**不建立任何任务**（零成本），
并把每个镜头的完整 body 打印出来。确认 `model` / `aspect_ratio` / `resolution` / `duration` 无误后再去掉它。
```bash
python3 scripts/i2v.py --model omni-reference --manifest /tmp/shots.json --dry-run --output-dir /tmp/mlty_out
```
返回 `status` 为 `dry-run` / `ok` / `partial` / `failed` / `empty`，直接看这个字段判断成败。

### 多张参考图（omni-reference）
`--image a --image b --image c` + **单个** `--prompt` 会自动折成「**一镜、三张参考图**」，
不会误跑成三次生成。要真的多镜请用 `--manifest`（一个 shot 对象里放 `"images": [...]`）。

### 硬闸门（omni-image）
首帧不是 16:9 时直接返回 `INPUT_NOT_16X9` 并拒绝建单 —— 因为 `omni-image` 只能用 `auto`，
非 16:9 的输入必然产出非 16:9 的片子。先跑 `@skill:emotion-performance-i2v` 的
`scripts/normalize_16x9.py`；确实要接受继承比例才加 `--allow-non-169`。

### 命名坑
输出文件名取自来源图文件名里的第一串数字（`re.search(r"(\d+)")`）。带日期的长文件名（如 `clipboard-2026-09-23T17-03-46.jpg`）会变成 `mlty_kling_2026_1.mp4`——先把参考图复制成 `ref_shot01.jpg` 这类干净名字。

### 本地 ffprobe 不可用
`/Users/mic/.local/bin/ffprobe` 不吃 `-show_entries` / `-select_streams`。查视频信息改用
`ffmpeg -hide_banner -i x.mp4 2>&1 | grep -E "Duration|Stream"`。

## 工作流（端到端）
1. 解析图片 → 本地文件先 `POST https://kieai.redpandaai.co/api/file-stream-upload` 拿 `downloadUrl`；URL 直接用。
2. `POST {KIE_API_BASE}/api/v1/jobs/createTask`（`model: kling-3.0/video`）建异步任务 → 拿 `taskId`。
3. 轮询 `GET .../api/v1/jobs/recordInfo?taskId=` 直到 `success`/`fail`。
4. 解析 `resultJson`（字符串需 JSON.parse）→ `resultUrls`（视频 URL 数组）。
5. 每个 URL 先 `POST .../api/v1/common/download-url` 换 20 分钟临时下载链接，再落地 `.mp4`。
6. 输出 JSON 汇总，含每条 `local_paths`、`duration`、`task_id`。

## 输出
- 文件：`mlty_kling_{shot:02d}_{n}.mp4`（默认 pro，可在 manifest 用 `mode` 覆盖）。
- 用 `present_files` 把生成的视频交给用户预览。

## 注意
- Kie.ai 结果 URL 24 小时内有效，生成后立即下载。
- 上传文件 24 小时过期，仅用于单次任务，不要长期依赖。
- 三个模型共用 `MODEL_REGISTRY` + `build_body` 的 `kind` / `ar_policy` 分派；加新模型只需往注册表加一项。
- API key 按模型分别解析（`MODELS.<model>.api_key`），缺失才回退到 `MODELS.kling`；
  环境变量 `KIE_KLING_KEY` / `KIE_OMNI_IMAGE_KEY` / `KIE_OMNI_REF_KEY` 可覆盖。
